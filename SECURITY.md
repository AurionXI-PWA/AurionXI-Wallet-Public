# Security reporting

Please do not post exploitable vulnerability details, wallet seeds, private
keys, PINs, authentication tokens or signing credentials in a public issue.
Use GitHub private vulnerability reporting if it is enabled; otherwise contact
the maintainer privately before sharing sensitive details. The repository does
not establish a new monitored security mailbox or promise a response time.

Source publication is not an audit certificate or a guarantee of fund safety.
Do not use real funds for unreviewed forks. Keep native signing, App Check,
transaction identity/nonce checks, caps and ambiguous-submission recovery intact.

If a credential is ever exposed, removing the visible file is not sufficient:
revoke/rotate it and review all reachable history and deployed systems.
